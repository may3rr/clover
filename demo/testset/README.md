# 预 2021 人类稿件测试集（构造注入实验用）

目的：用 2021 年（大模型普及）之前人类撰写的真实论文做底稿，人为注入错误后跑四层体检，
按**论断-引用对**（一条引用句 × 其引用的一篇文献 = 一个数据点）统计查准率、查全率、准确率。
收集时间：2026-10-24。原始包不入 git（见 `.gitignore`），本目录其余文件入库。

## 中文底稿的构建（`build_docx.py`，F33 重建）

底稿要像作者在 Word 里写的稿件：章节用标题样式，引用是上标 [n]，表格是 Word 表格，
插图是图片，中文标点保持全角。F8 版只从 PDF 逐行抽文字，章节标题并入正文、表格压成
文字、插图全部丢失，「表 1」还被改成了假引用「表[1]」，F33 起改为按版面重建：

- 四篇 PDF（知网下载版三篇，自动化学报官网版一篇）逐字读取字号与基线，先拼成行，再按
  两栏阅读顺序排列（通栏的图表把页面分成上下段，段内先左栏后右栏）。比正文小、位于
  正文行上方的数字写成上标引用；公式的上下标并回所在行。
- 编号标题只在编号承接上一个标题时才算标题（3.1.2 之后可以是 3.1.3、3.2 或 4），表格里
  的「1 段序列」之类不会被当成章节。
- 图按题注向上找图形区域截图；题注印在图片里的（罗会兰一篇）直接取图片。表格按表线
  定行列，三线表按文字列间空白定列。
- 页眉页脚、首页脚注（收稿日期、基金项目、作者简介）、页下脚注（①网址）、文末作者简介
  去掉。作者行按排版字距难以切分，作者名写在 `JOBS` 里。
- 期刊排版常把图表放在页顶，早于正文第一次提到它的位置；重建时把图表移到第一次提到
  「表 n」「图 n」的段落之后，和作者在 Word 里的放法一致，避免引用首次出现顺序被版面打乱。
  参考文献条目统一为半角标点。
- 顾迎捷一篇取软件学报官网 HTML 全文（`zh_html/jos_mrc_6048.html`，首次运行时下载，
  插图同目录缓存，不入库），章节、图表、上标引用都来自 HTML 结构。尹宏鹏一篇的参考
  文献沿用 `zh_refs/aas_yinhongpeng_odt.json`。

```bash
python demo/testset/build_docx.py            # 五篇全部重建
python demo/testset/build_docx.py tod -v     # 只建一篇，并列出被去掉的版面元素
```

重建后五篇的解析结果（`parse_document`）：

| --- | --- | --- | --- | --- | --- | --- |
| liuqiao_kg | 6 | 82 | 88 | 0 | 1 | 1 |
| luohuilan_odt | 5 | 69 | 90 | 0 | 0 | 6 |
| zhaoyangyang_tod | 6 | 239 | 220 | 1 | 10 | 8 |
| yinhongpeng_odt | 3 | 227 | 294 | 0 | 7 | 11 |

赵阳洋一篇未连上的 [0] 是公式里的上标原文。与 F8 版相比，刘峤一篇少了 9 个标记，
那是旧转换把脚注序号 ① 折算成「1」后误包成的 [1]；尹宏鹏、赵阳洋少掉的是作者单位上标
和错位的标记。

重建后重跑了注入实验（`results/summary.md`）：注入 44 处（罗会兰一篇的错别字词表只命中一处），
查全率 0.977，查准率宽 0.977、严 0.112，干净稿既有报警 340 条，支持度确定判断覆盖 68.3%。
F8 版对应为 0.933、0.894、0.075、515 条、45.4%。两次之间产品代码也有变化（文献文件夹、
本地原文核对等），差异不全来自底稿。尹宏鹏一篇的表格按原文顺序列出 [10]–[14]，晚于正文
已引的 [15] 之后各条，干净稿因此有成批的重排与重编号修订，这是原文的引用顺序。

## 中文底稿的知网下载清单

`zh_references.md` 中标注"中文"的 36 条 = 需要从知网下载的 PDF（放进各篇的 `ref/` 文件夹）。自动化学报那 8 条按刊物规范是拼音著录 + 括号内中文原文，检索知网直接用括号里的中文题名。
英文条目无需知网：真实性核验与支持度证据走联网检索（Crossref/OpenAlex/S2/arXiv）。

## 注入与评测流程

```bash
source /opt/anaconda3/etc/profile.d/conda.sh && conda activate claude
bash demo/testset/run_all.sh clean            # 五篇干净稿体检，产出注入白名单
python demo/testset/inject_corpus.py          # 每篇 9 处注入，seed=42，依赖 reports/*_clean.json
bash demo/testset/run_all.sh injected         # 五篇注入稿体检；reports/ 已有文件即跳过，重跑先删
python demo/testset/evaluate_corpus.py        # results/<paper>.json 与 results/summary.md
```

每篇注入 9 处，共 45 处：伪造文献 2、张冠李戴 2、错年 1、未引用条目 1、引用堆砌 1、错别字 2。
落点以干净稿报告为白名单：只改干净稿里产出论断的段落、论断真正引用的标记、在线核验通过的条目，
张冠李戴换入的文献须在干净稿里取到过原文。白名单保证每处注入原则上可检出，实验测的是检出能力，
解析盲区与原文覆盖率单独报告。注入在原有 run 内替换文字，保留 run 格式，干净稿与注入稿的差异
只在注入点。

### 英文语料

```bash
bash demo/testset/run_en.sh clean             # raw/ 五个 arXiv 源码包
python demo/testset/inject_latex.py           # 写 en_papers/<name>/manuscript_injected.zip，seed=42
bash demo/testset/run_en.sh injected
python demo/testset/evaluate_corpus.py en     # results/en_<name>.json 与 results/summary_en.md
```

注入类型与中文一致，错别字换成英文拼写错误。编辑落在解析器映射出的源码偏移上：
伪造与未引用条目按该篇自己的 .bbl 或 .bib 格式写入，张冠李戴改 `\cite{}` 里的键，
错年改 .bib 的 year 字段或 .bbl 条目里唯一的年份。未引用条目只注入 .bbl 项目（ResNet、GPT-3），
.bib 里没被引用的条目 BibTeX 不会输出，不构成错误，因此英文共 42 处注入。

## 指标

- 单元：一条引用句或一条参考文献为一个数据点。没有引用的句子上出现报警或注入时，该句单独成为一个单元。
- 正例：每处注入落在一个单元上，按该注入自己的检出规则判定 TP/FN。同一句上与注入无关的报警不算检出。
- 负例：其余单元。体检报出任一高/中严重度问题即为阳性，包括 support/distribution/norms 发现、
  unsupported 判定、not_found/mismatch、错别字修订。
- 干净稿既有报警：负例上的报警若干净稿在同一文本上也报了，单列。宽口径剔除这部分，严口径计为误报。
  这部分尚未人工核对，真实查准率落在两个口径之间。
- 支持度判定覆盖：拿到 supported/partial/unsupported 确定判断的引用句占比，单列，不进 P/R。
- 准确率以 TN 为主，只作参考。

## 已知局限

- 底稿由 PDF 版面重建，仍有转换痕迹：英文摘要个别单词的空格切分有误（知网 PDF 不含
  空格字符，按字形间距推断），公式是线性文字，个别表格的表头跨行合并不准，页下脚注
  没有保留。干净稿上的错别字修订有一部分在修这些痕迹。
- 解析器取条目中第一个非会议年份作为出版年，"Proc. of the 2014 Conf." 这类缩写会被当成出版年。
  错年注入只选只含一个年份的条目，不覆盖这一情形。
