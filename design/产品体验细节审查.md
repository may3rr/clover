# 产品体验细节审查

审查范围：`app/src/renderer/src` 全部屏幕与组件、`backend/citecheck/export/writer.py` 的批注写法、`overview/run.py` 的评审提示词、`demo/showcase_report.json` 与 `demo/demo_report_v2.json` 的 findings 文案，以及 `npm run shots` 离线截图（58 张，浅色与深色）和官网 stills。`design/对齐与边距改造清单.md` 已经覆盖的对齐、内边距、16 线、检查器标题字号、目录编号悬挂、孤字换行，本文不再重复。

## 1. 总体判断

现在最打动人的是三处：拖入后文件图标飞进骨架页、四个小助手逐层点亮的运行页；正文高亮与检查器联动，点一条就滚到原句；支持度详情里「你的论文写道」和「被引文献原文」并排，原文证据用底色标出。这三处已经达到 Notion 和 Linear 的完成度，评委会记住。

最影响观感的是**数字和措辞不一致**，以及**最好的证据藏得太深**。同一篇论文，运行页写 13 个问题，侧栏写 15，阅读区 callout 写 11，检查器标题又写 15，评委会追问哪个是对的。检查器按文档顺序排列，首屏多是灰色的「暂时无法核验」「未能获取原文」，红色的「被引文献不支持」「数据库中找不到」排在后面。系统核实过的 146 处引用在界面上没有任何痕迹，用户只看到问题，看不到工作量。还有一处会直接扣分：首次设置页把 OpenAI 和 DeepSeek 列为可选服务商，阿里云 Qwen 特别赛题的评委看到会出戏，也与 AGENTS.md「全程使用 Qwen 系列模型」不符。

## 2. 路演演示路径走查

以 `demo/narration.txt` 的顺序走一遍，假设演示机已完成引导，用 `showcase_paper.docx` 或 `demo_paper.docx`。

| 步骤 | 用户看到什么 | 哪里会卡或出戏 |
| --- | --- | --- |
| 0 启动 | 引导页 `the last mile of the paper` 字体轮换，第二步「连接模型服务」 | 第二步列出阿里云百炼、OpenAI、DeepSeek 三个品牌图标，Qwen 赛题评委会注意到。表单一次给出 API Key、接口地址、拉取模型列表、快速模型、深度复核模型五项，第一次使用信息过载。底部分页圆点压在「只复核有疑问的判断」这行说明上。 |
| 1 首页 | 「把论文拖到这里」，下面两段共约 120 字的说明，三个胶囊按钮和一个期刊输入框 | 第二段说明里有两处多余空格（「根目录， PDF」「支持度， 填写」），是 JSX 换行造成的。「arXiv 计算语言学」胶囊没有标签，点开只有这一个选项，评委不知道它是什么。中文论文也默认对标 arXiv 计算语言学。没有示例论文入口，想自己试的评委要先找一篇 docx。 |
| 2 拖入文件夹 | 扫描页显示真实阶段，随后进入「核对文献连接」 | 连接页标题下说明有一处「原文。 连上的」多余空格。侧栏「没有原文」用了带勾的徽章图标，「待确认」用了论断支持度的对话气泡，语义对不上。每行标题和 PDF 文件名几乎相同，视觉上像重复。 |
| 3 运行页 | 文件名、总进度、骨架页逐页点亮、四层进度条 | 副标题固定写「通常需要一两分钟」，缓存命中时 8 秒就完成，和报告里「检查用时 8 秒」自相矛盾。进度条上方左侧也写「正在检查」，与副标题重复。等待期间只有百分比，看不到任何已经发现的内容，这是整场最长的空白。运行中没有取消按钮，拖错文件只能等完。 |
| 4 报告打开 | 论文标题、属性行、callout「发现 11 条需要注意」、期刊评审卡、正文高亮 | callout 的 11 把低严重度的「无法判断」也算进「需要注意」，侧栏写 15，检查器写「15 个问题」，三处数字都不同；15 里还含 4 处错别字修订，修订并不是问题。属性行只有文件、引用标记数、参考文献数、对标领域、用时，看不出系统核验了多少条、比对了多少处原文。 |
| 5 点第一条问题 | 检查器首屏 | 真实性组首条之后连着两条灰色「暂时无法核验这篇文献」，依据写「检索服务暂不可用」，在路演里读起来像系统坏了。`showcase_report.json` 里就有这样的条目。支持度组前面是三条「未能获取这篇文献的原文」。最能说明产品价值的红色条目要往下滚。 |
| 6 支持度详情 | 标题、四五行「依据：……建议：……」长段落、「你的论文写道」卡、「被引文献原文」卡 | 380px 检查器里，原文卡大多在折叠线以下，演讲者要边讲边滚。原文卡没有写出判定（不支持 / 部分支持）和「证据已逐字定位」这件事，产品最值钱的可信度机制在界面上不可见。来源行「依据开放全文」放在卡片最底部。 |
| 7 真实性详情 | 「检索的文献数据库中均未找到这篇文献」，下面是自己写的五个字段 | 看不出查了哪几个库。DOI 为空时显示「—」。没有让作者自己复核的入口（比如去 Crossref 搜这个标题），评委会问「怎么证明不是你没搜到」。 |
| 8 期刊评审卡 | 五个维度与整体评语 | 模型输出夹英文字段名，如 `demo_report_v2.json` 里「0表格0图， exemplars含2至27张表」「exemplars通常覆盖更广」「支持度低6项」。评语「更接近未完成草稿」偏重。 |
| 9 导出到 Word | 胶囊按钮转圈，弹出「已导出」浮层，打开文件 | 浮层写「保存在 Downloads 文件夹」，中文系统下访达显示「下载」。浮层不说写入了多少条批注、多少处修订，这一步是「提效闭环」的收尾，少了一句有分量的话。Word 里的批注只有标题和依据、建议，没有被引原文，作者在 Word 里看不到证据，要切回 Clover。 |
| 10 收尾 | 回到报告 | 如果彩排时收起过侧栏或检查器，这个状态会存在 localStorage 里，正式演示一打开就是收起的；此时点正文高亮会打开一个看不见的详情，画面没有反应。 |

## 5. 不建议做的事

- **不要给不支持的论断生成改写建议或替代文献。** 「建议改成……」「可以改引 XX」都踩产品原则第 2 节的红线，即使评委问到也只演示批注。第 19 条的 Crossref 链接只是检索入口，不给候选。
- **不要做一个总分或百分制「引用健康度」。** 一个数字会被追问怎么算，和「不确定就说不确定」冲突；分层计数已经足够。
- **不要把 146 处已核实的引用全部在正文里涂绿。** 正文会被颜色淹没，问题反而不突出；48 小时内用第 3 条的属性行把工作量写出来即可。
- **不要为路演加庆祝动画、彩带或音效。** 6.4 规定的动效体系已经克制统一，额外特效会拉低质感。致谢页的音乐彩蛋留给问答环节，不进 3 到 5 分钟的主线。
- **不要改动引导页的英文衬线标语与字体轮换。** 它是现有的记忆点，改动成本高、收益低。
- **不要在现场网络上从零跑一篇新论文。** Semantic Scholar 和 OpenAlex 在样例里单源累计耗时超过 100 秒，会场网络不可控；演示用缓存命中的稿件，第 7 条的预案要提前演练。
- **不要在检查器里加卡片式汇总面板或图表页。** 6.3 禁止一排排相同圆角卡片，引用分布的图已经在详情里，主界面保持三窗格。
- **不要在 48 小时内改 LaTeX 导出或参考文献重排逻辑。** 路演只演示 docx 闭环，LaTeX 作为「也支持」一句话带过。
