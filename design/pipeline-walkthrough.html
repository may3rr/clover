Clover（citecheck）流水线说明，基于 backend/citecheck/pipeline.py 与 2026-10-31 的一次真实体检

一篇 docx 怎样变成一份引用体检报告

稿件在本机被解析成带坐标的段落、引用标记和参考文献条目，随后四个图层并发运行：真实性核验查数据库，支持度把每条论断和被引原文交给 Qwen 判断，分布和规范以本地统计与规则为主。所有结果汇成一个 Report 对象，前端渲染成阅读视图，导出时问题变成 Word 批注，机械性改动变成修订。

下文用演示稿《基于深度学习的目标检测研究综述》中的一句话做例子，从 XML 一路跟到 Word 批注。

3 跟着一句话走一遍

例句来自演示稿第 2 节讲 SPP-Net 的一段。原文写“快了 240 ~1020 倍”，SPP-Net 论文摘要里写的是 24–102 倍。这个错误是 demo/final/injections.json 有意注入的“数字放大十倍”，下面看系统怎样一步步把它找出来。

2014 年He 等人[20]提出了空间金字塔网络( Spatial Pyramid Pooling Network，SPP-Net) 检测算法，它在CNN最后一层卷积层和全连接层之间加入SPP层(如图2所示)，使得网络能够输入任意尺度的候选区域，从而每张输入图片只需一次CNN运算，就能得到所有候选区域的特征，这使得计算量大大减少．SPP-Net的检测速率比R-CNN 快了240 ~1020 倍[20]，并打破了固定尺寸输入的束缚．
1
解析：XML 变成带坐标的对象lxml + 正则，无模型

docx 是一个 zip，正文在 word/document.xml。解析器逐个读 <w:r>，拼出段落纯文本并记住每个字符来自哪个 run；上标 run 里的 [20] 被识别为引用标记。参考文献表里的 [20] 条目由编号连到标记上。

输入：document.xml 片段
<w:p>
  <w:r><w:t>2014 年He 等人</w:t></w:r>
  <w:r><w:rPr>
    <w:vertAlign w:val="superscript"/>
  </w:rPr><w:t>[20]</w:t></w:r>
  <w:r><w:t>提出了空间金字塔网络…快了240 ~1020 倍</w:t></w:r>
  <w:r>…superscript…<w:t>[20]</w:t></w:r>
  <w:r><w:t>，并打破了固定尺寸输入的束缚．</w:t></w:r>
</w:p>
输出：Paragraph / CitationMarker / Reference
Paragraph {

  char_offset: 2412,

}

  raw: "[20]", kind: "superscript", ref_ids: ["r20"] }

坐标是贯穿全程的主键。之后每个论断、问题和修订都用 {paragraph_id, start, end} 指回这段文字，前端靠它高亮，导出时靠它切分 run 挂批注。标记识别的优先级是 Zotero / EndNote 域代码，其次上标 run，最后正则匹配 [1]、(Smith, 2020)、张三等(2020) 等写法。

复核级联

首判 judge得到 label
→
partial / unsupported交 review 再判；原文是本地全文时，先用双语检索词重新挑一个更大的片段
supported同模型再做一次细节核对：数值、名称、方向、单复数等；发现可定位的冲突也送 review
off_topic 但证据未定位必须由 review 确认才显示为“可能引错文献”

review 失败时改用 review_fallback，再失败保留首判结果。当前配置里三个任务都指向 qwen3.8-flash；10 月初的 demo_report_v2 里 review 用的是 qwen3.8-max。

7
证据逐字校验确定性，不可跳过

模型给的 evidence 和原文片段两边都做 Unicode NFKC 归一化、压缩空白、统一引号，然后做子串匹配。对 PDF 断词连字符和被拆开的拉丁词另有两层宽松匹配。定位到的位置换算回原片段坐标，存为 evidence_span。

r20 摘要（1659 字符）中两条证据的位置
01659
c10 证据 span [363, 480]，校验通过，supported 保留 c11 证据 span [1280, 1425]，校验通过，unsupported 保留
定位失败时：先让模型重答一次，要求原样摘抄连续片段或承认无法判断；仍然失败就把 label 降级为 undetermined，rationale 写“证据未能在原文中定位”。界面上能看到的每一个“支持 / 不支持”，都能在原文里找到对应的句子。

7 几处值得注意的地方

模型只在需要语义判断的地方出现标记识别、统计、格式规则、重排和证据校验都是确定性代码。模型负责拆条目、抽论断、判支持度、分功能、找错字，每次输出都要过 pydantic 校验和后续规则过滤。
依赖链决定了耗时本次各层耗时：规范 0.3 s，真实性 19.5 s，分布 20.8 s，支持度 29.9 s。支持度排在最后，因为它要等真实性拿到摘要或 PDF 链接，并且调用次数最多。
两条独立路径互相印证“He 等人[21]提出了 Fast R-CNN”同时被作者归属规则（f11，不需要原文）和支持度模型（f10，读了原文）判出。
拿不到原文是主要的空白107 个判断中有 20 个因为没有原文而无法判断，集中在 13 篇文献上（多为中文文献和付费期刊）。把这些 PDF 放进 ref/ 文件夹后，本地原文会优先于联网来源。
中文稿件对标英文基线没有填写期刊或范文不足时，分布层用 150 篇 arXiv 计算语言学论文做基线。语言不同时只比占比，并且综述类章节（canonical=other）不产生分布问题。
